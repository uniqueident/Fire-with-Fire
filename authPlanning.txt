 IMPLEMENTATION CHECKLIST: SECURE SSO FOR CHROME EXTENSION 
 ============================================================================
 

 1. MANIFEST.JSON SETUP & PERMISSIONS
    - [ ] Add "identity" permission for chrome.identity.launchWebAuthFlow.
    - [ ] Add "storage" permission for chrome.storage.session and chrome.storage.local.
    - [ ] Add "alarms" permission to schedule background token refreshes.
    - [ ] Add host_permissions for your IdP domains (authorization, token, JWKS endpoints).
    - [ ] Set a static "key" in manifest.json so the extension ID and redirect URI never change.
    - [ ] Generate redirect URI via chrome.identity.getRedirectURL() and whitelist it in your IdP.

 2. IDENTITY PROVIDER (IdP) CONFIGURATION
    - [ ] Client ID (public client type; never bundle client secrets in extension files).
    - [ ] Authorization endpoint URL.
    - [ ] Token exchange endpoint URL.
    - [ ] JWKS endpoint URL (for public keys used in token signature verification).
    - [ ] Token revocation and logout endpoint URLs.
    - [ ] Scopes list: "openid", "profile", "email", and "offline_access" (for refresh tokens).

 3. CRYPTOGRAPHY & PKCE HELPERS (Web Crypto API)
    - [ ] Secure random string generator using crypto.getRandomValues (base64url-encoded).
    - [ ] Code Verifier generator: 43 to 128 character high-entropy random string.
    - [ ] Code Challenge generator: SHA-256 digest of verifier, base64url-encoded (S256).
    - [ ] State generator: one-time high-entropy random string to prevent CSRF / login injection.
    - [ ] Nonce generator: cryptographic random string to prevent OIDC token replay.

 4. SSO FLOW INITIATION
    - [ ] Build authorization URL with parameters: client_id, response_type=code, redirect_uri,
          scope, code_challenge, code_challenge_method=S256, state, and nonce.
    - [ ] Persist pending auth state ({ state, code_verifier, nonce, timestamp }) in
          chrome.storage.session so it survives if the service worker goes idle during login.
    - [ ] Call chrome.identity.launchWebAuthFlow({ url, interactive: true }) to open the login window.
    - [ ] Support silent session checks via launchWebAuthFlow({ url, interactive: false }).

 5. CALLBACK PARSING & ANTI-CSRF VALIDATION
    - [ ] Handle user cancellation and window closure errors via chrome.runtime.lastError.
    - [ ] Parse returned callback URL query parameters (code, state, error, error_description).
    - [ ] Strict state verification: verify returned state exactly matches stored state; abort if mismatched.
    - [ ] Immediately delete consumed state from storage to enforce one-time usage.

 6. TOKEN EXCHANGE (Code -> Tokens)
    - [ ] Send POST request to IdP token endpoint with Content-Type: application/x-www-form-urlencoded.
    - [ ] Pass: grant_type=authorization_code, client_id, code, redirect_uri, and raw code_verifier.
    - [ ] Receive response containing: access_token, refresh_token, id_token, and expires_in.
    - [ ] Strip/sanitize tokens from any debug or network logs.

 7. ID TOKEN & CLAIMS VALIDATION
    - [ ] Parse JWT structure into header, payload, and signature.
    - [ ] Fetch and cache IdP public keys from JWKS endpoint.
    - [ ] Cryptographically verify signature using crypto.subtle.verify (RS256 or ES256).
    - [ ] Verify standard claims:
          * iss: must strictly match trusted IdP issuer URL.
          * aud: must match your extension client_id.
          * exp: current time must be before expiration (with 1-2 min clock skew allowance).
          * nbf: current time must be after 'not before' timestamp (if present).
          * nonce: must match the nonce saved in step 4.
    - [ ] Extract user profile claims (sub / user ID, email, name, avatar).

 8. SECURE STORAGE & DATA ISOLATION
    - [ ] Store active access_token in chrome.storage.session (in-memory only, wiped on browser exit).
    - [ ] Restrict session storage via chrome.storage.session.setAccessLevel({ accessLevel: 'TRUSTED_CONTEXTS' }).
    - [ ] Manage refresh tokens safely:
          * Preferred: proxy refresh tokens via backend BFF with HTTP-only secure cookies.
          * Alternative: store encrypted in chrome.storage.local for cross-session persistence.
    - [ ] NEVER store tokens in localStorage, web page DOM, or within content script memory.

 9. PROACTIVE TOKEN REFRESH & CONCURRENCY MUTEX
    - [ ] Compute expiration timestamp: Date.now() + (expires_in * 1000).
    - [ ] Schedule background refresh 60-120 seconds before expiration using chrome.alarms.
    - [ ] Implement a concurrency mutex / queue: ensure multiple simultaneous API calls wait on
          a single refresh request instead of sending duplicate requests (protects Refresh Token Rotation).
    - [ ] On refresh failure / invalid_grant: clear stored tokens and notify UI to prompt re-login.

 10. SECURE INTER-COMPONENT MESSAGING
     - [ ] Keep all token handling in the background service worker (single source of truth).
     - [ ] Provide message handler for UI contexts (popup/options) to query auth state (isAuthenticated, profile).
     - [ ] Content script protection: NEVER send raw tokens to content scripts.
     - [ ] For authenticated API calls from content scripts: content script sends request message to background;
           background attaches Bearer token, performs fetch(), and returns only sanitized response data.
     - [ ] Validate message senders in chrome.runtime.onMessage: enforce sender.id === chrome.runtime.id.

 11. LOGOUT & REVOCATION
     - [ ] Wipe credentials from chrome.storage.session and chrome.storage.local.
     - [ ] Cancel any scheduled refresh alarms in chrome.alarms.
     - [ ] Evict Chrome identity cache via chrome.identity.removeCachedAuthToken.
     - [ ] Call IdP revocation endpoint (POST /oauth/revoke) to revoke refresh/access tokens.
     - [ ] (Optional) Launch IdP end-session / logout URL if global corporate SSO sign-out is required.

 12. SECURITY AUDIT & ERROR HARDENING
     - [ ] Enforce HTTPS for all authentication and API endpoints.
     - [ ] Redact tokens and credentials from error handlers, telemetry, and console outputs.
     - [ ] Handle network failure, offline states, and timeouts gracefully with exponential backoff.
     - [ ] Verify compliance with Manifest V3 Content Security Policy (no remote scripts, no eval).
