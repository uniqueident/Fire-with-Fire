MVP IMPLEMENTATION CHECKLIST: PASSWORDLESS .EDU SSO FOR CHROME EXTENSION
============================================================================
Goal: Minimal viable passwordless authentication system with strict .edu
email verification, SHA-256(email + token) hashing, and local browser storage.
============================================================================

1. EXTENSION SETUP (manifest.json)
   - [x] Add "identity" and "storage" to permissions.
   - [x] Add your IdP domain to host_permissions (e.g., https://*.google.com/*).
   - [x] Get your redirect URL via chrome.identity.getRedirectURL() and whitelist it in your IdP dashboard.

2. AUTH CONFIGURATION (config.ts)
   - [x] Client ID (configured as a Public Client / Single Page App; no secrets).
   - [x] Authorization endpoint URL.
   - [x] Token exchange endpoint URL.
   - [x] Scopes (e.g., "openid email profile").

3. PKCE & CRYPTOGRAPHIC HASHING (pkce.ts)
   - [x] Generate random `code_verifier`, `code_challenge` (S256), `state`, and `nonce`.
   - [x] Strict `.edu` email format validator (`validateEduEmail`).
   - [x] SHA-256 hash generator: `hashTokenAndEmail(email, token)` using Web Crypto API.
   - [x] 6-digit confirmation code generator.

4. LOGIN FLOW (chrome.identity & Passwordless Email)
   - [x] SSO Login: Check that the returned profile is strictly a `.edu` email address.
   - [x] Passwordless Email Verification: User inputs `.edu` email; extension generates verification code/link.
   - [x] Cryptographically hash `email + token + salt` upon verification.
   - [x] Store verified user credential on browser extension for future SSO access.

5. BROWSER STORAGE (storage.ts)
   - [x] Save active session tokens in `chrome.storage.session`.
   - [x] Save persistent verified `.edu` user credential in `chrome.storage.local`.
   - [x] Resume verified user session on startup without re-entering credentials.
   - [x] Logout: clear session tokens.
============================================================================

Authentication Design:
   - Email: Strictly ending in .edu (e.g. user@university.edu)
   - Password: Completely removed (Passwordless)
   - Stored Token: SHA-256(email + token + salt) stored in browser extension
